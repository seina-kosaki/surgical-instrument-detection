# logger仕様

## 目的

通常の自作Pythonコードの出力を標準ライブラリの `logging` に統一し、コンソールと日別ログファイルに記録する。本仕様はユーザーが「この仕様でOK」と合意した内容を記載する。

## 入出力

- 入力：自作コードから渡すログメッセージ、ログレベル、ロガー名。
- 出力先：コンソール、およびプロジェクト直下の `logs/YYYY-MM-DD.log`。
- ファイルはUTF-8とし、日時・レベル・ロガー名・メッセージを記録する。日時とファイルの日付はローカル時刻基準とする。
- 既定のログレベルは `INFO`。必要時に `DEBUG` へ変更できる。

## 使用方法

- 起動時に `setup_logging(level=logging.INFO)` を呼び出す。引数を省略した場合も `INFO` とする。戻り値はない。
- `setup_logging(level=logging.DEBUG)` を再度呼び出すことでログレベルを変更できる。レベルには標準ライブラリの `logging` が受け付ける整数またはレベル名を使用する。不正なレベルは例外として通知する。
- 呼び出し側では `logging.getLogger(__name__)` でロガーを取得し、`logger.info(...)` などで記録する。
- ログ書式は `2026-11-04 20:00:00 [INFO] モジュール名: メッセージ` とする。
- コンソール出力先は標準エラー出力（stderr）とする。
- ファイルの作成・書き込み・日付切替に失敗した場合は例外を呼び出し元へ伝播し、処理を停止する。コンソールのみへの切り替えは行わない。

## 動作

1. アプリケーション起動時にロギングを初期化する。
2. 設定したレベルに従い、コンソールとログファイルの両方へ出力する。
3. 同じ日付のファイルには、再起動後も追記する。
4. 継続稼働中に日付が変わった場合、その後のログは新しい日付のファイルに記録する。
5. 初期化を繰り返しても同一ログが重複出力されないようにする。
6. 保存期間は無期限とし、過去のログファイルを自動削除しない。
7. ログ保存先は作業ディレクトリではなく本モジュールの配置を基準としたプロジェクト直下とし、必要なディレクトリを自動作成する。
8. ルートロガーに出力先を登録する。再初期化時は本モジュールが登録したハンドラーのみを置き換え、他のハンドラーは削除・クローズしない。

## 責務

- `src/logging_config.py`：ロギングの初期化、レベル設定、両出力先への記録、日付切替、再初期化時の重複防止を担う。実装はこの1ファイルに収める。
- 呼び出し側：起動時に初期化し、通常の自作コードの出力には `print` ではなくloggerを使用する。
- `logs/`：日別ログファイルの保存先。

## 制約・対象外

- Python 3.12、標準ライブラリ `logging` を使用し、追加依存は導入しない。
- 既存の `print` の自動置換や捕捉は行わない。
- `docs/agent-customization-spec.md` のPython方針に従い、まず動作する最小構成を優先する。型アノテーション・docstring等の整備を初期実装の必須条件としない。
- 同文書の「設定ファイルは基本YAML」という方針は、今回の設定ファイル新設を要求するものではない。本仕様では設定ファイルの追加を要求しない。
- 合意していない機能を追加しない。
- 実装対象は `src/logging_config.py` と、その動作確認に必要なテストとする。エージェント設定は変更しない。

## 受け入れ条件

- 既定の `INFO` ログがコンソールと当日のログファイルの両方に記録され、日時・レベル・ロガー名・メッセージを確認できる。
- `DEBUG` に変更すると `DEBUG` ログを記録できる。
- 同日中に再起動しても既存ログを保持し、同じファイルへ追記される。
- 継続稼働中の日付変更後、新しい日付のファイルへ記録される。
- 日本語メッセージがUTF-8のファイルに正しく保存される。
- 初期化を繰り返しても、各出力先で同一ログの重複が発生しない。
- 過去のログが自動削除されない。
- ファイルの作成・書き込み・日付切替の失敗が、呼び出し元に例外として通知される。

## 未解決事項

なし。公開API、レベル変更、ログ書式、コンソール出力先、ファイル出力失敗時の扱いはユーザー合意済み。

## 次工程への引き継ぎ

本仕様に対する変更は、ユーザーの実装指示に基づいて行う。変更後は自動テストを実行し、ユーザーに手動確認を依頼する。手動確認の成功が報告されるまで、任意のコード整備は開始しない。
